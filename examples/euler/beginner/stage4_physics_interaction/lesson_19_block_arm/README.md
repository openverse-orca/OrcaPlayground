# 第 19 课：积木臂登场

## 本课效果
积木臂立在桌心，肩关节匀角速扫过 110°、肘钳定 0°——整条臂像一根
刚体梁旋转。终端实测梁上两个点的弧线速度：梁根的肘盘（r≈0.20m）
和梁端的推球头（r≈0.385m）——每点 v/r 都等于角速度 ω，速度比
≈ 半径比 1.9。梁端先后追尾推走两个球，外球明显更快。

## 准备
同第 01 课（OrcaPlaygroundAssets 订阅，含积木臂 block_arm）。

## 运行
```bash
python -m examples.euler.beginner.stage4_physics_interaction.lesson_19_block_arm.run --default-scene
```

## 关键代码
只让**一个关节转起来**，运动链自动联动：
```python
qpos[qadr] = rate_rad * t      # 肩关节角脚本（弧度）
qpos[e_qadr] = 0.0             # 肘关节钳定 0°（详见下文「肘为什么要锁」）
qvel[vadr] = rate_rad          # 肩角速度；肘角速度同拍清 0
env.set_joint_qpos(qpos); env.set_joint_qvel(qvel)
env.do_simulation(ctrl, sim_link.FRAME_SKIP)  # 步进：梁在此追尾两球
```
与 18 课的本质区别：绕圈课写的是整个物体 6 个自由度的位姿；积木臂
只让肩关节**1 个自由度**转起来——前臂、推球头由 MuJoCo 运动学树自动
联动。用少量关节角控制整个机构，这就是机械臂「少控多动」的本质，
也是阶段 5 真机器人关节控制的雏形。

## 动手改
配方区 `SWEEP_RATE = 30.0` → `60.0`：角速度加倍，梁上每点线速度都
加倍（下一节挑战就是预测这个）；`SWEEP_ANGLE = 110.0` → `60.0`：
臂只扫一半，内球（110° 方位）不会被追尾——终端会给出未推动警告。

## 解释结果
- **梁上两点 v/r 都 ≈ ω（实测 0.525/0.526 vs 理论 0.524 rad/s）**
  ——刚体上的点做纯圆周运动，v = ω·r 精确成立；速度比 1.93 ≈
  半径比 0.385/0.20 = 1.92。风扇叶尖比根部快、摩天轮边缘比中心快，
  都是这条公式
- **为什么测梁不测球**——球贴梁**侧面**被推时，球心走在比接触点更大
  的圆上（球心速度 = ω×接触点半径，天生小于 ω×球心半径），数值永远
  对不上公式；两球只作定性印证（外球/内球速度比 ≈ 2，梁端扫得快）
- **两球先后被追尾（外球 38° 先、内球 110° 后）**——两球半径和 0.30m，
  同方位摆不下（会重叠互弹），分方位摆放各吃一击
- **臂全程不减速**——关节角是脚本写入的（无限强伺服），球的阻力对它无效
- **肘为什么要锁**——肘是被动关节（本课还没给它写脚本），球撞前臂的
  反作用力会把肘一路踢弯、前臂不断「让劲」，推球变成蹭球；钳定 0° 后
  整条臂像铸铁，两球都被干净推行。下一课让肘真正动起来

## 小挑战
先预测再验证（predict）：把 `SWEEP_RATE = 30.0` 改成 `60.0`，
梁上两点（肘盘、推球头）的弧线速度各变成多少？两者的速度比呢？
- 提示：v = ω·r，ω 加倍 → 每点速度都加倍；速度比 = 半径比，
  与 ω 无关，仍是 ≈1.9
写下你的预测，运行对照，看每点速度是否精确翻倍、比值是否纹丝不动。

## 常见问题
| 现象 | 修复 |
|---|---|
| 未找到积木臂 | 场景里要有 block_arm（拖入或 --default-scene） |
| 臂不转 | 确认 body 名含 arm_base 且其子 body 有铰链关节（默认配方即满足） |
| 球被推出桌外 | 30°/s 的追尾推不出去——被推出多半是**视口拖拽干扰**，演示期间请勿在视口中拖动物体 |
| 球莫名移动/下沉 | 同上：OrcaLab 视口里的鼠标交互会物理推动物体（ActorManipulator），运行课程时手离开视口 |
| 场景里有多个臂/球 | 课程取第一个臂、离臂最近的两个球；建议清理后重跑 |
