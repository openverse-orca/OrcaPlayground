# 第 17 课：调整时间步长

## 本课效果
两组各推进 1 秒仿真时间（实时节拍，视口可见下落全过程）：步长 0.002s 认真走了
500 步稳稳落地；0.01s 大步只走 100 步，但落地瞬间被接触求解器**弹回半米高**。
这就是"精度"和"算力"的交易现场——省 5 倍步数，代价是接触事件不可信。

## 准备（二选一，体现你的主导权）
- **你的场景（倡导）**：沿用前面课摆好的方块
- **兜底**：加 `--default-scene`，脚本用默认配方（地面 + 抬高一米的方块）

## 运行
```bash
# 方式 A：用你自己的场景
python -m examples.euler.beginner.stage3_simulation_time.lesson_17_change_timestep.run

# 方式 B：默认配方兜底
python -m examples.euler.beginner.stage3_simulation_time.lesson_17_change_timestep.run --default-scene
```

## 关键代码
```python
env = sim_link.connect_simulation_env(addr, time_step=0.01)  # 步长是构造级参数
n_steps = int(round(SIM_DURATION / ts))                       # 1s / 0.01s = 100 步
for _ in range(n_steps):
    sim_link.advance_realtime(env, ctrl, 1)   # 实时节拍，视口可见下落
```
**仿真时间**（引擎里的 t）和**墙钟时间**（你手表上的秒）是两回事：
500 步 0.002s 组也许比你手快、也许比你手慢，但仿真时间里它精确走了 1 秒。

## 动手改
配方区 `TIME_STEPS` 改成 `(0.001, 0.02)`：拉大 20 倍差距，观察大步长组
落地高度偏差是否变大；`SIM_DURATION` → `2.0`：翻倍时长再对比。

## 解释结果
- 步数严格成比例（500 : 100 = 5:1）——这是定义，不是巧合
- **两组末高度差很大（约 0.9 m）且大步长组反而更高**：自由下落段两组轨迹几乎
  重合（t=0.5s 时只差厘米级——飞行段对步长不敏感），但落地后粗步长下接触求解器
  对碰撞冲量解算过冲，把方块弹回了半米高。不是 bug，是本课最生动的教学点
- 步长太大（如 0.05s）还会让接触抖动甚至穿透——RL 训练里调不好 reward，
  有时根子在这里

## 小挑战
**算步数**：把 `TIME_STEPS` 改成 `(0.004, 0.008)`，先笔算两组各需多少步
（1.0 / 0.004 = ?、1.0 / 0.008 = ?），再运行验证日志里的步数与你的答案一致。

> 步长是仿真世界的"像素大小"——会算步数，才算真的理解了时间步进。

## 常见问题
| 现象 | 修复 |
|---|---|
| "未找到方块" | 拖入/自 spawn 一个含 "cube" 名字的方块，或加 `--default-scene` |
| 大步长组方块落地后被弹起老高 | 预期现象：粗步长接触求解过冲，正是本课要展示的精度代价 |
| 两组末高度几乎一样 | 换更粗糙的步长（如 0.02）或更高落差；自由飞行段对步长不敏感，接触瞬间才是分水岭 |
| 墙钟耗时波动大 | 墙钟受机器负载影响，只看量级；精确对比请以步数为准 |
