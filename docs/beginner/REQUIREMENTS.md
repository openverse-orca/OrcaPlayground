## 1. 背景与问题

### 1.1 为什么要重构

当前 OrcaPlayground（`dev` 分支）由两批内容构成：

| 板块 | 内容 | 服务对象 |
|---|---|---|
| `examples/euler/`（01–11 课） | Hello Euler → 在线渲染 → 环境注册 → PPO 训练 → 查询 API → 外力 → 雅可比 → G1 行走 → 视频录制 → 体操作 → 场景配置 | OrcaGym 开发阶段的验证载体 + 开发者 |
| `examples/embodied/`（character/cloth/fluid/g1/drone/d12 等） | 机器人项目、耦合仿真、策略推理 | 算法与引擎开发者 |

问题：仓库实际服务的是**开发者验证**，而产品目标用户是**会写少量 Python、但没有机器人/物理仿真/强化学习经验的新手**。两者对"第一课"的期待完全不同：

1. **第 1 课就有完整 Gym API**。`01_hello_euler/simple_env.py` 的单摆环境包含 action space、observation space、reward、随机 reset——新手第一次打开就被 Gymnasium 全套概念淹没。
2. **第 4 课就上 PPO**。强化学习出现在入门第 4 课，违背"RL 是进阶路线而非门槛"的定位。
3. **第 5–10 课全部依赖 G1 人形关卡**。`assets/g1/` 约 60 个 STL 网格 + 17 个 ONNX 策略模型，资产重、前置条件多（OrcaLab + G1 关卡 + 订阅资产），新手无法在前三课内"看见结果"。
4. **课程梯度断层**。从"单摆步进"直接跳到"G1 雅可比 IK"，中间缺少场景编辑、物理直觉（重力/摩擦/碰撞）、单关节控制、差速小车等过渡台阶。
5. **配套版本耦合脆弱**。课程隐式依赖特定 OrcaGym 提交与 OrcaLab 版本组合，未在课程元数据中锁定；已知问题包括资产注册竞态（首次运行报"资产包未订阅"）、`append_scene()` 等接口在部分版本缺失。

### 1.2 重构目标

基于设计文档，将仓库重建为**新手优先的示例库**：

- 阶段一：用户能说"我能把东西放进去并摆好"（场景 + 资产 + 编辑）
- 阶段二：用户能说"我知道仿真怎么推进，知道摆位和施力的区别"（物理直觉）
- 阶段三：用户能说"我能控制机器人完成小任务并判断成败"（控制 + 任务）
- 强化学习后置为选修路线（A01–A08），不是进入 Playground 的门槛

完整规划为 **48 个基础课 + 8 个选修专题**，首版只交付 **01–18**。

本分支（`feat/playground-beginner-redesign`）从接近空的状态重建新手主线，**最终整体替换 `dev` 分支**：旧内容（Euler 01–11 课程、embodied 高级样例）在合入主线时移除，不保留为独立入口；需要旧内容的用户经由 git 历史标签访问（决策记录见 §11）。

## 2. 用户分析

### 2.1 目标用户画像

| 属性 | 描述 |
|---|---|
| 编程基础 | 会运行 Python 脚本、能改几行代码；不熟悉 conda 以外的环境管理细节 |
| 领域经验 | 无机器人学、无物理仿真、无强化学习经验 |
| 工具环境 | 安装了 OrcaLab（含 OrcaStudio 视口）的 Windows/Linux 机器，可能有 GPU |
| 学习方式 | 按目录顺序尝试，期望"改一个数字 → 立刻看见变化"；遇到报错会复制粘贴到搜索引擎 |
| 失败容忍度 | 低。前 10 分钟内看不到画面/结果即流失 |

### 2.2 非目标用户（本期不服务）

- 需要 GPU 集群训练大规模策略的 RL 研究者 → 指向 OrcaGym 文档与独立研究仓库（本库不承载）
- 需要流体/布料/XPBD 耦合仿真的引擎开发者 → 指向 OrcaGym/OrcaEngine 仓库文档（原 dev 分支示例随替换移除）
- 想直接加载自有 USD/MJCF/URDF 资产的资产工程师 → 选修 A08 扩展工坊

### 2.3 核心用户故事（首版 01–18 范围）

1. 作为新手，我打开 `START_HERE`，按一条命令跑通第一课，在 OrcaStudio 视口里看到地面和一个方块。
2. 作为新手，我加载一个已订阅的资产（球/桌子/机器人），理解"资产路径"和"实例"的区别。
3. 作为新手，我修改场景配方里的一个坐标数字，重新运行后看到方块位置变了。
4. 作为新手，我暂停/单步仿真，看到方块下落一格，理解"物理步进"。
5. 作为新手，我读取方块的高度数值并打印，看到它随时间减小。
6. 作为新手，我改重力为 0，看物体悬浮，建立物理参数直觉。
7. 作为新手，我让一个物体沿正弦路径往返运动，理解"用代码驱动仿真"。
8. 每课完成后，我知道下一课是什么、它需要什么前置。

## 3. 现状与能力边界（需求可行性核对）

### 3.1 已核对可复用的现状资产

| 现状内容 | 位置（dev 分支） | 新库复用方式 |
|---|---|---|
| Euler 课程骨架与文档风格 | `examples/euler/TUTORIAL.md` + 各课 `0X_*.md` | 复用文档 8 节结构与统一教学模板 |
| 自包含目录原则 | 每课含全部 `.py`，`__file__` 上溯定位资产 | 沿用，改为 `lesson_XX_name/` 合法标识符目录 |
| 入口脚本模式 | `main()` + argparse + `_create_env_with_retry()` + 顶层 try/except | 提炼进 `_common`，重试逻辑需针对资产竞态加强（见 §7.2） |
| 场景构建三步范式 | `OrcaGymScene(addr)` → `add_actor(Actor(...))` → `publish_scene()` | 阶段 1–2 课程的核心机制 |
| 单摆/障碍物等轻量 MJCF | `assets/scenes/simple_pendulum.xml` 等 | 阶段 3–5 教学模型参考 |
| OrcaLab 外部程序菜单 | `.orcalab/config.toml` | 保留，新增新手课程启动项 |
| 安装/环境文档 | `README.md`、`AGENTS.md` 规则 1 | 复用 `orca` conda 环境约定 |

### 3.2 三个影响落地的能力边界（继承自设计文档，作为需求约束）

1. **资产加载 ≠ 任意文件导入**：首版"导入物体/机器人/场景"仅指加载 OrcaLab 已订阅的 spawnable 资产；自有格式转换、碰撞体制作进入选修 A08，不进主线。
2. **编辑摆放 ≠ 运行时物理控制**：Actor 创建参数（position/rotation/scale）表达初始摆放；运行期移动物体走自由关节位姿写入 / Mocap / 外力 / 执行器，按资产类型选择。课程 07–09、12 首版采用"编辑配方 → 重建教学场景"路线，需在课程中明示"会重新加载和复位"。
3. **两仓库必须锁定配套版本**：OrcaGym / OrcaLab(服务端) / Playground / 资产包四元组合必须在课程元数据中声明并实测。已知风险：`append_scene()` 在部分 OrcaGym 版本缺失；`PublishScene` 会销毁全部已生成实体再重建。

### 3.3 已知问题（必须在新库中规避，来自既有实践）

| 问题 | 对新库的需求影响 |
|---|---|
| 引擎侧 spawnable 资产表一次性填充，云端订阅资产晚注册检测不到，首跑报"资产包未订阅" | 入口脚本必须有带退避的重试 + 明确"重启 OrcaLab"提示（FR-N06） |
| 直接发布场景后立即关闭导致运行态丢失（灯光设置等） | 教学场景必须保持存活至仿真结束（FR-N08） |
| Euler 体系 `set_joint_qpos` 只接受全量数组（Local 体系接受 dict） | `_common` 提供 dict→全量数组转换助手（FR-F20） |
| `OrcaGymDataView.time` 是快照，`mj_step` 后需显式同步 | 教学代码模板固化正确的时间读取方式 |
| 物体位置同步到 O3DE 视口需 `step()` 触发完整同步管线，仅 `render()` 无效 | 课程模板规定"步进 + render"的最小循环结构（FR-N07） |
| `PublishScene` 重新发布会销毁此前所有实体 | 增量场景更新必须重加全部累计 Actor（写入 `_common` 场景助手） |
| MJCF 缓存（`~/.orcagym/tmp/*.xml`）导致加载旧/空场景 | 排障文档覆盖缓存清理（FAQ 模板） |

## 4. 功能需求

编号规则：`FR-<阶段><序号>`，F=功能，N=非功能。阶段映射设计文档的 8 个教学阶段 + 选修。
优先级：P0=首版必须（01–18 课 + P0 配套确认），P1=第二批（19–36），P2=第三批（37–48），P3=选修。

### 4.1 课程体系需求（继承设计文档 §3，此处只列需求级条目）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-S01 | 课程总数 48 + 8 选修，目录名 `lesson_01_hello_world` 式合法 Python 标识符，编号即推荐学习顺序 | P0 定义 / 全量 P2 |
| FR-S02 | 首版交付 01–18（阶段 1 场景资产 + 阶段 2 编辑 + 阶段 3 时间流动），且每课可独立启动、独立复位 | P0 |
| FR-S03 | 每课只引入一个主要知识点；每课含一个可调参数 + 一个小挑战；关键代码 10–30 行 | P0 |
| FR-S04 | 前三课内必须"看见结果"（OrcaStudio 视口画面或明确的终端成功输出）；前 12 课不出现 reward/action space/observation space 概念 | P0 |
| FR-S05 | 每课统一教学模板：本课效果/准备/运行/关键代码/动手改/解释结果/小挑战/常见问题/下一课（9 节） | P0 |
| FR-S06 | 课程间知识有先后但运行时无依赖：不继承上一课残留场景、速度、外力 | P0 |

| FR-S08 | 选修课（A01–A08）不作为基础课安装前提；RL/训练依赖仅在对应选修课安装 | P3 |

## 7. 接口需求与外部依赖（需向 OrcaGym 侧确认/申请）

### 7.1 已确认存在（阅读版本），可直接使用

`Actor`/`add_actor()`/`publish_scene()`、`do_simulation()`/`reset()`/`render()`、`set_joint_qpos()/set_joint_qvel()`（全量数组）、`mj_forward()`、`env.sim_config`、`set_time_step()`、`apply_body_force()`/`clear_body_force()`/`clear_all_forces()`、`set_geom_friction()`、`query_joint_qpos()/query_joint_qvel()`、`set_ctrl()`、`query_contact_simple()/query_contact_force()/query_sensor_data()`、`mj_jac_site()`、`set_camera_sensor_info()`/`begin_save_video()`。

### 7.2 需在 P0 配套确认中验证或补齐

| 项 | 现状 | 需求 |
|---|---|---|
| 普通 Actor 的运行时单实例删除 | 未找到公共入口 | 首版走"配方移除→重建"；若需热删除，向 OrcaGym 提接口需求 |

- 不支持 OrcaStudio 的 scene spawn（仅 OrcaLab，文档明示）

## 8. 验收标准（首版发布门槛）

1. 新环境按文档安装后，**无需修改源码中的硬编码本机路径**即可运行 01–18 全部课程。
2. 资产/服务端/配套 API 缺失时，启动前给出明确问题与修复提示（不裸栈退出）。
3. 同一课运行两次：无重复实例累积、无速度/外力残留（FR-N04）。
4. 每课只加载所需依赖；在未安装 torch/onnxruntime 的环境跑通 01–18。
5. 屏幕结果与 `docs/beginner/previews/` 相符；数值类学习目标有真实校验（自由落体高度变化、关节误差收敛、成功判定）。
6. 后端支持按实测标注；不把"Euler Env 类名"等同于"全部计算走自研后端"。
7. 缩放课验证视觉与碰撞一致性；重建课验证名称索引重载；控制课验证动作单位与执行器类型。
8. ruff SLF001 对新库零报警。
9. 每课元数据含"已验证版本组合"，且该组合在发布前完整回归一遍。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 资产注册竞态导致首跑失败（引擎侧一次性填充表） | 高 | FR-N06 脚本侧退避重试 + "重启 OrcaLab"提示；同步上报引擎侧根治 |

| 规模失控（48 课全量铺开） | 中 | 坚持先做 01–18 内的纵向样板课，定型后再填充 |
