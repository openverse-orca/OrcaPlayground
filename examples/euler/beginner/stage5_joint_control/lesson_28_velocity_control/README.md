# 第 28 课：速度伺服

## 本课效果
终端先打印速度伺服轮的铭牌（ctrlrange ±10 rad/s），然后发 +3 rad/s：
轮子指数式越转越快（黄色辐条肉眼可辨），t63 实测 ≈0.9 s，稳态精确
3.00 rad/s。再发 −3 rad/s 反转：从 +3 跨到 −3，时间常数不变、稳态
精确 −3.00——正反转完全对称。

## 准备
同第 01 课（OrcaPlaygroundAssets 订阅，含速度伺服轮 wheel_velocity）。
轮子默认悬空（轴心 0.8 m），轮底离地 0.5 m——不接触地面，物理干净。

## 运行
```bash
python -m examples.euler.beginner.stage5_joint_control.lesson_28_velocity_control.run --default-scene
```

## 关键代码
同一行 ctrl，本课写的是**目标转速**：
```python
ctrl = sim_link.zero_ctrl(env)
ctrl[0] = 3.0                       # 目标转速（rad/s）——"请转 3 弧度每秒"
env.do_simulation(ctrl, sim_link.FRAME_SKIP)   # 伺服把差值一点点抹平
```
速度伺服的出力规则：力矩 = kv ×（目标转速 − 当前转速）。差越大推得
越猛、差为零就撒手——这就是指数爬升的来源：I·dω/dt = kv·(ω_target−ω)，
解是 ω(t) = ω_target·(1−e^(−t/τ))，时间常数 τ = I/kv = 0.09/0.1 = 0.9 s。

## 动手改
配方区 `TARGET_SPEED = 3.0` → `6.0`：稳态精确变 6.00，但爬升时间常数
**不变**（见小挑战）；`WATCH_S = 7.0` → `4.0`：窗口缩短后稳态读数
会差 1% 左右（指数趋近的残余），正好体验「观察窗口要覆盖足够多的
时间常数」。

## 解释结果
- **稳态 3.00（±0.01），没有静差**——对比 27 课位置伺服的 1.9° 静差：
  这里轮轴水平、质心在轴上，重力矩为零；速度伺服「差为零就撒手」
  恰好够用（27 课的位置伺服差为零就出不了力扛重力，必须留误差）
- **t63 ≈ 0.9 s**——一阶系统的时间常数定义：完成 63.2% 变化量的时刻
  （e⁻¹=0.368，剩余 36.8%）。τ = I/kv = 0.09/0.1，刻意的软增益让
  爬升过程在视口看得见
- **反转时间常数相同**——伺服只看「目标与当前的差」，不看方向；
  从 +3 到 −3 变化量是 6，从 0 到 +3 变化量是 3，各自的 63.2% 时刻
  都是 0.9 s
- **正反转完全对称**——物理里没有「顺时针更省力」的规矩；如果
  实测不对称，先查轮子是否蹭到了别的物体（见常见问题）

## 小挑战
先预测再验证（predict）：把 `TARGET_SPEED` 改成 `6.0`，两件事——
1. 稳态转速是多少？
2. 爬升到稳态的时间变长了吗？t63 还是 0.9 s 吗？
- 提示：稳态精确 6.00（目标就是目标）；τ = I/kv 里没有目标转速，
  时间常数与目标幅值无关，t63 仍是 0.9 s——指数曲线只是被「拉高」，
  形状（快慢）不变

## 常见问题
| 现象 | 修复 |
|---|---|
| 报错 nu=0 | 场景里的轮子没有执行器——本课需要 wheel_velocity（拖入或 --default-scene） |
| 稳态差 0.02~0.05 rad/s | 检查轮子是否蹭到别的物体或地面（默认悬空不会） |
| 反转明显更慢 | 视口里轮子被拖拽过或有物体搭在上面，清理后重跑 |
| 看不清转向 | 黄色辐条就是风向标；凑近视口看辐条划过的方向 |
